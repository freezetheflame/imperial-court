# Imperial Court (朝堂) — 需求基线

> 本文档是 grill-me 会话的产物，记录所有已确认的决策。任何后续变更必须先改这里。

## 定位

- **两者并重**：真实可用的 multi-agent 编排系统 + 沉浸式皇帝体验。
- **制度是一等公民**：支持多重制度换装，制度定义角色体系、职权边界、通信协议、汇报链路、权力制衡。
- **任务与制度解耦**：通用事务任务、通用工具集，换制度不改任务层。

## 第一套制度：三公九卿（简化版）

八个岗位（三公 + 四部 + 御史助手）：

| 官职 | 角色 | 职责映射 |
|------|------|----------|
| 丞相 | 总协调 | 承接上谕 → 拆解任务 → 分派执行岗 → 汇总上奏 → 催办 |
| 太尉 | 对外联络 | 对外公共沟通、社交类功能、皇帝不便出面的对外事务 |
| 御史大夫 | 监察主审 | 御史台主审：查证 + 判断 + 弹劾直奏 |
| 治粟内史/少府 | 财务资源岗 | 资源、预算、数据统计类任务 |
| 廷尉 | 司法质检岗 | 审核把关、成果复核、合规检查 |
| 典客/宗正 | 关系外部岗 | 外部关系、对接、接待类任务 |
| 郎中令/卫尉/太仆/奉常 | 内务服务岗 | 内部事务、文档、杂务执行 |

御史台 = 御史大夫（主审，查证+判断）+ 御史×1（助手，协助查证/起草简报）。

## 治理机制

- **汇报链路**：执行岗 → 丞相 → 皇帝（标准）；御史台 → 皇帝（特权直奏，唯一例外）。
- **奏折状态机**：呈报 → 已读 → 批红（准/驳/留中/发回重办）→ 归档。
- **驳回/发回重办**：一律打回丞相重新分派，由丞相指定分工。
- **汇报时机**：任务终报；丞相有权催办中期进度。
- **越权控制（初版）**：工具白名单 + 消息路由拦截（A+B 两层），分层设计，后续演进权限矩阵（C）。
- **判定分层**：确定性判定（规则引擎，硬约束，不交 LLM）vs 智能判断（御史 agent，软逻辑）。
- **弹劾流程**：越权拦截 → 违制记录 → 御史台 → 弹劾奏章（特权直奏）→ 皇帝裁决。
- **职位变动（初版两档）**：革职（需皇帝朱批）+ 留任警告（御史台自决记档）。
- 弹劾案全程入弹劾表，皇帝可随时翻阅。

## 技术架构

| 项 | 决策 |
|----|------|
| 语言 | Python（后端）+ TypeScript/React（前端） |
| Agent 循环 | 自研薄循环 + 现成 LLM SDK（OpenAI 兼容） |
| 模型 | DeepSeek API；丞相用 pro（发布前 flash 顶替），其余岗位 flash |
| 规则引擎 | 静态 YAML（白名单查表）+ 动态策略函数 + 统一判定接口 |
| 消息总线 | 进程内 asyncio 异步总线（消息对象走路由层校验） |
| 存储 | SQLite 单库，薄封装不引 ORM；事件表 = 史册 = 御史台数据源 |
| 任务执行 | 异步化，前端实时展示进行中状态 |
| 前端 | React 18 + Vite + TS + Tailwind + React Query + SSE |
| 交付 | API 契约先行，设计稿 + 契约交 kimi 落地前端 |
| 平台 | Kylin aarch64 早期开发，Windows/WSL x86_64 平滑迁移 |

## 测试策略

- **协议层测试**（制度无关）：pytest 验证 agent 循环、消息收发、上下文管理。
- **行为层测试**（制度相关）：场景剧本（scenario fixtures）验证各岗位表现。
- **验收标准**：每岗一组能力验收用例，全部通过且结果可复现才算"定下来"。
- **调试手段**：调 prompt / 换模型 / 改循环，全档开放。
- 测试资产（用例、失败记录、prompt 迭代历史）存"测试档案"，换制度时复用已验证的能力块。

## 明确不做（初版 Out of Scope）

- 皇帝主动查岗/主动要求调查（御史台只被动收弹劾）
- 降职/调任（职位变动只做革职 + 留任警告）
- 权限矩阵 C 层（数据层拦截）
- 自由拟旨（上谕用结构化表单）
- 外部消息中间件（Redis/RabbitMQ/Kafka）

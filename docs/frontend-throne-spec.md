# 前端交互设计 Spec — 金銮殿沉浸式体验（v2）

> 目标：把现有"网页管理后台"UI 升级为"皇帝坐镇金銮殿"的沉浸式交互。
> 用户坐在龙椅上：奏折递交到手里、起身移驾御史台、翻阅百官名册，
> 丞相有事上报时有"进殿呈奏"动画。
> 本 spec 是 codex 的实施指令。先读 `frontend/src/` 现有代码和 `docs/api-contract.md`。

## 核心原则

1. **场景化而非页面化**：整个应用是一个"金銮殿"世界，用户视角固定为皇帝御座。
   现有功能（奏折批红/上谕下达/弹劾裁决/官员任命）全部保留，只是换交互载体。
2. **纯 CSS/SVG，零图片素材、零新依赖**：人物用 SVG 剪影，场景用 CSS 渐变+透视+装饰元素。
   离线可跑，不引 three.js / 图片库 / icon 库。
3. **动画即反馈**：新奏折到达、丞相进殿、批红、移驾，都有明确动画。
4. **不破坏现有功能与数据流**：REST 端点、SSE、Query 缓存逻辑全部不动。

## 场景实现细节

### 1. 金銮殿主场景（`ThroneHall` 组件，新）

**视觉**（全部 CSS/SVG）：
- 大殿背景：深色木质柱廊（CSS 渐变 + 重复元素），地面用透视网格/木板纹理渐变营造纵深
- 中轴线布局：龙椅位置即用户视角（屏幕底部中央是御案边缘）
- 御案：前景元素，放朱批笔架（SVG）、未读奏折堆（数量=待批奏折）
- 殿柱：左右两侧对称 CSS 柱体（古木色渐变 + 顶部斗拱简化）
- 匾额：顶部"正大光明"或"奉天承运"（SVG 文字）
- 香炉/烛火：角落装饰（CSS 动画微动）

**布局**：不再用现有侧边栏 Layout。新组件替代 `Layout.tsx` 的角色，
但保留路由结构（大殿=首页 `/`，御史台=/censorate，名册=/posts，上谕=/edicts 变为"拟旨"交互）。

**交互**：
- 御案上"待批奏折"堆：点击 → 展开最近一封奏折（卷轴动画）→ 批红按钮（准/驳/留中/发回）
- 御案两侧交互点（可用"玉牌/令牌"样式按钮）：移驾御史台、翻阅百官名册、拟旨下谕
- 顶部或角落：当前日期/时辰（可省略）、紧急事件提示（弹劾急报用红色令牌动画）

### 2. 丞相进殿呈奏动画（核心亮点）

触发：SSE 收到 `memorial` 事件（chancery 呈报）时。

动画序列（CSS keyframes + React state）：
1. **殿门提示**：远景殿门出现丞相剪影（SVG：幞头+朝服，深色剪影），缓步前移
2. **走至丹陛**：剪影从殿门移动到中景丹陛前（transform translate + 时间差）
3. **躬身呈奏**：剪影做"躬身"姿态（SVG 整体 rotate/scale 微动），双手托起
4. **奏折飞来**：一封奏折（卷起的 SVG/div）从丞相位置沿弧线飞向御案
   （CSS transition + 贝塞尔曲线，或两段 transform 模拟抛物线）
5. **落案展开**：奏折落到御案 → 展开成卷轴（scaleX 从 0 展开 + 内容渐显）
6. **等待批红**：卷轴保持打开，显示批红按钮；批红后卷轴合上，丞相剪影谢恩退下（反向动画）

整个动画约 3-4 秒，可跳过（点击跳过）。动画期间不阻塞其他操作。

### 3. 移驾切换（`SceneTransition`）

- 点击"移驾御史台"→ 大殿整体淡出 + 轻微缩放 → 御史台推入
- 返回："回銮"按钮 → 反向
- 切换动画 ~500ms，用 CSS transition + 两个场景绝对定位叠放

### 4. 御史台场景（改造 `CensoratePage`）

视觉：案卷库——深色木架背景，弹劾案卷像一排卷宗立放。
- 在审案件：卷宗立牌（标题"弹劾 XXX"、类型章、红色"待裁决"标记）
- 点击卷宗 → 展开成案卷详情（证据/简报/拟议）→ 朱批准奏/驳回
- 顶部统计改为"案卷登记簿"样式（小牌）
- 保留现有 API 调用与数据

### 5. 百官名册场景（改造 `PostsPage`）

视觉：名册典籍——打开的书/册页背景（CSS 双页效果或简化为木简/告示牌）。
- 每岗位一张"官牌"：官职名（大字）、品秩（model）、状态印（在职朱红/空缺金/革职灰）
- 空缺岗位：官牌有"待任命"印章，点击 → 任命交互（保留现有）
- 点击官牌可查看详情（职责、隶属、现任 agent）

### 6. 拟旨下谕（改造 `EdictsPage`）

视觉：御案上展开一卷空白圣旨（卷轴样式）。
- 表单字段融入圣旨排版（标题/事务类别/正文/着令岗位）
- 颁布按钮："颁布上谕"（盖玉玺动画：红色方印落下）
- 历史上谕：圣旨卷轴列表（已颁布的卷起，可展开查看）

## 技术约束

1. Tailwind v4（@theme token 已有：imperial-vermillion/gold/parchment/wall/ink），
   可补充 token（如殿木色、丹陛色）
2. React 19 + TS，`verbatimModuleSyntax` → `import type`
3. **不改 `frontend/src/lib/api.ts` 接口、不改后端**（数据形状见 api-contract.md）
4. **保留 SSE 实时刷新**（`useEventStream` 不动），动画由 SSE 事件触发
5. **不新增 npm 依赖**（纯 CSS/SVG）
6. 动画用 CSS keyframes + React state 控制，不用动画库
7. 路由结构保留：`/`（大殿）、`/censorate`、`/posts`、`/edicts`；
   Layout 组件可被替换为"大殿壳"，但 NavLink 语义（场景切换）保留
8. 完成后必须 `npm run build`（tsc -b && vite build）通过
9. 响应式：窄屏时大殿元素缩小/隐藏装饰，交互点仍可点

## 验收标准

1. `npm run build` 通过
2. 打开首页是金銮殿场景（非普通列表），有明确沉浸感
3. SSE 收到奏折 → 丞相进殿呈奏动画出现 → 可批红
4. 移驾御史台/名册 → 场景切换动画 → 功能可用 → 可回銮
5. 上谕下达有圣旨+玉玺交互
6. 现有功能不丢：批红、裁决、任命、SSE 刷新
7. 代码干净：无未用 import、类型正确、CSS 复用（组件/类）

## 建议实现顺序

1. `ThroneHall` 大殿场景骨架（背景/御案/殿柱）+ 替换 Layout
2. 奏折卷轴组件（展开/合上动画）+ 批红交互
3. 丞相剪影 SVG + 进殿呈奏动画（SSE 触发）
4. 移驾切换 + 御史台/名册场景化改造
5. 拟旨圣旨交互
6. build 验证 + 自测

## 风格参考

- 色彩：朱红 #8b1a1a、金色 #a67c00、宣纸 #fdf8f0、深宫墙 #351818
- 人物剪影：深色（近似 #2a1a1a），简化为"幞头+宽袖朝服"轮廓，约 60-90px 高
- 卷轴：宣纸底 + 上下深色木轴（CSS 小矩形）
- 印章：朱红方框双线（现有 .seal 样式可复用）
